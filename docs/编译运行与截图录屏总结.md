> 操作步骤（含每步点击位置）见 [`运行与录屏指南.md`](运行与录屏指南.md)；本文只回答三件事：**怎么编译运行、截图怎么来的、录屏怎么来的**，以及哪些环节与官方推荐方式不同、为什么。

## 2. 编译与运行

### 2.1 两条等效路径

| 方式 | 操作 | 适用场景 |
| --- | --- | --- |
| **A. IDE 图形界面** | 打开工程 → Sync → `Run 'entry'`（▶） | 日常开发、断点调试 |
| **B. 命令行 hvigor** | `hvigorw.js --mode module -p product=default -p buildMode=debug assembleHap` | 可脚本化、可复现、便于批量重装与自动化截图 |

本项目**两种都验证过**：功能开发用 A，批量产出截图/录屏用 B（因为需要反复「卸载 → 重装 → 冷启动」，图形界面做这个太慢）。

### 2.2 命令行编译的实际写法

DevEco 自带 Node 与 hvigor，不需要另装环境：

```bash
DEV="<DevEco Studio 安装目录>"
export NODE_HOME="$DEV/tools/node"
export DEVECO_SDK_HOME="$DEV/sdk"

"$DEV/tools/node/node.exe" "$DEV/tools/hvigor/bin/hvigorw.js" \
  --mode module -p product=default -p buildMode=debug assembleHap --no-daemon
```

成功标志：`> hvigor BUILD SUCCESSFUL in ~14 s`，产物在 `entry/build/default/outputs/default/`。

> 注意：不配置签名时产出的是 `entry-default-unsigned.hap`，只能装到模拟器/已开调试的真机，不能上架。本项目验收场景够用。

### 2.3 安装与启动

```bash
HDC="<DevEco>/sdk/default/openharmony/toolchains/hdc.exe"

# 安装（首次不带 -r，重装带 -r）
"$HDC" file send entry-default-unsigned.hap /data/local/tmp/dormlink.hap
"$HDC" shell bm install -p /data/local/tmp/dormlink.hap -r

# 冷启动：必须先 force-stop，否则拿到的是旧进程与旧内存态
"$HDC" shell aa force-stop com.xuhao.dormlink
"$HDC" shell aa start -a EntryAbility -b com.xuhao.dormlink
```

**一条必须记住的规则**：想要「全新安装」的冷启动状态（界面显示「未检测到有效存档」），必须 **先 `aa force-stop` 再 `bm uninstall`**。应用在运行时 `bm uninstall` 会失败但不报错，导致数据残留、冷启动直接恢复到旧存档——这个坑实际踩过一次，第一次录屏前半段全是旧数据。

## 3. 截图

### 3.1 两种方式

| 方式 | 做法 | 特点 |
| --- | --- | --- |
| IDE 截图按钮 | 模拟器工具栏相机图标 | 手动、逐张，适合少量 |
| **命令行 `snapshot_display`** | `hdc shell snapshot_display -f /data/local/tmp/s.jpeg` + `hdc file recv` | 可脚本化，适合「操作 → 截图」串联 |

本项目 12 张全部用命令行采集，流程是：

```
uitest dumpLayout  →  拿到控件文本与中心坐标
uitest uiInput click/swipe  →  驱动界面到目标状态
snapshot_display + file recv  →  落地为 jpeg
```

用文本找控件而不是硬编码坐标，是因为 UI 改版后坐标会漂移（本项目 UI 从深色改米家浅色、TabBar 换图标、加设备详情页，坐标变过 3 轮）。

### 3.3 截图环节的三个坑

1. **Tab 切换动画中间态**：点 Tab 后立刻截屏，会拍到两个页面并排的过渡帧（曾误判为「布局横向溢出」）。解决：点击后等 1.5–2 秒再截。
2. **应用启动比预期慢**：`aa start` 后固定等 6 秒仍可能白屏（拿到空布局）。解决：等 8–9 秒，或先 `dumpLayout` 确认关键控件出现再截。
3. **控件坐标要换算**：截图分辨率与 `uiInput` 坐标系不同（本项目截图 497×1040、设备 1260×2720，约 2.535 倍）。按截图量出来的坐标去点会点空。

## 4. 录屏

### 4.1 官方方式与限制

HarmonyOS 官方录屏链路（`hdc shell screenrecord` / 系统录屏应用）**仅支持真机**。本项目使用的 Huawei_Phone 模拟器镜像：

- 不含系统「录屏」应用；
- `screenrecord` 不可用；
- DevEco 模拟器工具栏也没有录屏按钮。

所以「模拟器上按官方方式录屏」这条路走不通。

### 4.2 实际采用的替代方案

**对模拟器窗口按固定帧率连续抓帧，再用 H.264 合成视频**：

```
Windows GDI PrintWindow 抓取模拟器窗口
  → 裁剪到设备画面区域（8,8,505,1048）
  → 缩放 400×836
  → 18 fps 连续保存 JPEG 帧
  → imageio + libx264 合成 mp4
```

| 参数 | 值 |
| --- | --- |
| 帧率 | 18 fps（视觉上足够流畅，体积可控） |
| 时长 | 124.4 秒 |
| 帧数 | 2239 帧 |
| 体积 | 5.23 MB |
| 编码 | H.264（`libx264`，quality 8） |

### 4.3 视频内容分镜

| 时间 | 内容 |
| --- | --- |
| 0:00–0:08 | 冷启动，提示「未检测到有效存档」 |
| 0:08–0:16 | 规则页滚动查看 6 条规则 |
| 0:16–0:48 | R002 / R003 / R004 / R001 逐条改数据 → 执行 → 看设备 |
| 0:48–1:00 | 启用 R006，时段改 8 点，验证窗帘通道冲突 |
| 1:00–1:08 | 切无人，R005 触发，拦截 3 个 |
| 1:08–1:18 | 删光条件保存 → 「规则不合法」提示 |
| 1:18–1:30 | S2 场景冲突 → 一键修复 |
| 1:30–1:38 | 日志页核对记录 |
| 1:38–1:48 | 生成测试报告 12/12 |
| 1:48–2:04 | 强制结束进程 → 重启恢复 |

### 4.4 必须如实说明的两点

1. **这是「模拟器窗口截帧合成」，不是设备端原生录屏**。画面是真实运行输出（每一步都由 `uiInput` 真实点击触发，数据由规则引擎真实计算），但不是系统级录屏文件。报告中已注明。
2. **截帧期间不要移动/最小化模拟器窗口**，否则会拍到桌面或黑屏。脚本里做了 `IsIconic` 检测并自动还原，但仍建议全程不碰窗口。

## 5. 测试运行

| 套件 | 命令 / 操作 | 结果 |
| --- | --- | --- |
| Node 纯逻辑 | `cd tests/node && npm test` | **20 / 20 通过**，耗时约 210 ms |
| DevEco hypium | IDE 右键 `ohosTest` → Run 'Tests in entry' | 14 条，需在 IDE 内运行 |
| 应用内自检 | 应用「日志」页 → 生成测试报告 | 12 条断言全通过 |

**hypium 为什么不能命令行跑**：该模拟器镜像的 testRunner 未随 HAP 打包，`aa test` 返回 0 但无输出。所以对外证据统一用 Node 侧 20 条（真实 TAP 输出见 `docs/测试运行日志.md`），hypium 作为「在真实 ArkTS 运行时也能跑」的补充。

## 6. 环境层面的坑与规避

| 现象 | 原因 | 规避 |
| --- | --- | --- |
| `hdc` 命令长时间无响应，`dumpLayout` 超时 | hdc server 长跑后会卡死 | 脚本里对每次调用设 25 s 超时，超时后自动 `hdc kill` + `hdc start` 重试 |
| `need connect-key? please confirm a device` | hdc 与模拟器连接丢失 | 重启 hdc；仍失败则重启模拟器 |
| 模拟器桌面卡在搜索页且杀不掉 | `com.ohos.sceneboard` 是 keep-alive 进程 | 放弃桌面图标，改用 `aa start` 直接拉起应用 |
| 批量删除 2000+ 帧被拦截 | 安全策略对批量删除有阈值 | 每次录制用新帧目录，不删旧目录 |
| 重新生成报告报 `Permission denied` | 文档被 editor_sdk 实例占用 | 先关闭编辑实例再跑生成脚本 |

**唯一缺口是真机原生录屏**。若后续能借到 HarmonyOS 真机，补录方式：

1. 真机开启开发者模式与 USB 调试，`hdc list targets` 确认设备；
2. 用系统「屏幕录制」快捷开关，或 `hdc shell screenrecord /data/local/tmp/demo.mp4 --time-limit 180`；
3. 录完 `hdc file recv /data/local/tmp/demo.mp4` 取回，替换 `screenshots/demo-recording.mp4`；
4. 同步更新 `README.md` 第 8 节的「诚实说明」段落（删除模拟器截帧的说明）。
