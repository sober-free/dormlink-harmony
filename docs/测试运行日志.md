## 4. 测试说明与验收对照

1. **Mock 输入构造**：`Environment`（温度/光照/湿度/时段/在室）与 `AutomationRule` 全部以本地对象构造，不依赖任何真实硬件或云服务；设备状态用 `cloneDevices(DEFAULT_DEVICES)` 生成，保证每条用例输入独立、可重复。
2. **预期结果判定**：对设备终态、`triggeredRuleIds` 顺序、`records[].order`、`conflicts` 内容、`warnings` 关键字做断言；冲突用例明确断言「R002 胜出、R005 空调动作被拦截、R005 其他动作仍执行」。
3. **回归**：`[边界 5]` 对 4 组预设场景各执行两次并比较终态与触发顺序，验证规则引擎无随机性、可复现。
4. **对应评分项**：核心功能实现（触发顺序 / 冲突优先级 / 执行日志）、数据持久化（存档 round-trip 与损坏降级）、异常处理（越界、NaN、非法规则、损坏存档）均有可运行断言支撑。
5. **待补证据**：DevEco Studio 内 `ohosTest` 的测试通过截图与真机运行录屏需在实机补录，见 `docs/运行与录屏指南.md`。
